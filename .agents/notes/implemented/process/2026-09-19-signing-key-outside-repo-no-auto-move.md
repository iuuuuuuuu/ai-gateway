# Agent Note: 签名密钥固定在仓库外，且刻意不自动搬运

Status: implemented

## Problem

原 `docs/DECISIONS.md` D13（从 DECISIONS.md 迁移）。

`createUpdaterArtifacts` 恒为 `true`（`src-tauri/tauri.conf.json`），
所以 `tauri build` **必须**拿到签名私钥，否则客户端拒绝更新包。

私钥**不入库**（`.gitignore` 排除 `*.key` / `*.key.pub`）。本仓库是**公开仓库** ——
被 git 跟踪的文件里出现口令是**不可撤销**的泄露：即使随后删除，历史里仍然在。

历史上有过两代目录（`.wb-switch` 与更名期的 `.ai-gateway`），
于是自然产生一个念头：**让脚本把旧路径的私钥自动搬到新路径**。
这个念头必须被明确否掉，否则迟早有人实现它。

## Decision

签名私钥与口令放在**仓库之外**；`scripts/build-signed.ps1` 的 `Resolve-KeyPath`
按**首选 → 回退**解析：

| 顺序 | 路径 |
|---|---|
| 首选 | `%USERPROFILE%\.wb-switch\wb-switch-updater.key` / `.password` |
| 回退（1.0.0 / 1.0.1 更名那一代） | `%USERPROFILE%\.ai-gateway\ai-gateway-updater.key` / `.password` |

走回退路径时脚本打印**黄色提示**，**但绝不自动搬运私钥**。

### 为什么不自动搬运

脚本注释写明了理由：

> **私钥丢失即无法再为已发布客户端签名。**

自动搬运会引入这些**不可恢复**的路径：

- 搬运中途失败（断电、进程被杀）⇒ 目标不存在、源可能已删
- 只搬了一半（密钥搬了、口令没搬）⇒ 两个文件不配对，且看起来都"存在"
- 覆盖了目标位置已有的**另一把**密钥 ⇒ 已发布客户端的更新链断裂

**宁可多一条回退分支，也不自动搬私钥。** 回退分支最坏的情况是「提示你去手工处理」，
自动搬运最坏的情况是「两把密钥都没了」。

### 必须承认的代价：实际路径与默认探测不一致

实际密钥放在**仓库根的同级 `keys\` 目录**（即仓库之外，
`.gitignore` 已排除 `*.key` / `*.key.pub`）⇒ 脚本默认的两处路径
**在本机都不存在**，**必须**用 `-KeyFile` / `-PasswordFile` 显式指定：

```powershell
& ".\scripts\build-signed.ps1" -KeyFile "<密钥路径>" -PasswordFile "<口令路径>"
```

⚠ `.github/workflows/release.yml` 头部注释里写的
`%USERPROFILE%\.ai-gateway\ai-gateway-updater.key` 是**过时口径** ——
以 `build-signed.ps1` 的 `Resolve-KeyPath` 为准。`release.yml` 里那句只影响
「本地路径提示」，CI 走的是 secrets，不受影响。

### 其它已踩过的坑

- `TAURI_SIGNING_PRIVATE_KEY` 的值必须是密钥**内容**，不是路径。传路径会报
  `failed to decode base64 secret key: Invalid symbol 58`（路径里的冒号）。
- **缺口令时 `tauri signer sign` 不报错，而是阻塞等待 stdin 输入**，
  表现为「构建卡住」；口令**错误**才会秒级报错。非交互场景务必先 `-CheckOnly`。
- 加密私钥的 keynum 偏移（**54..62**）与公钥（**2..10**）不同，**不能直接比对**；
  判断配对的唯一可靠方式是**实际签一次**再比签名与公钥的 keyid。
- keyid = `7e7ce64b6fc3a36f`。旧口径 `217C0E2B4321D841` 是**错的**，
  照它比对会误判成「密钥不配对」。

## Alternatives considered

- **私钥入库** — 它最强的理由是**彻底消除路径问题**：密钥跟着仓库走，
  任何机器 clone 下来就能构建，不需要 `-KeyFile`、不需要回退分支、
  也不会出现「默认路径不存在」这种摩擦。否掉的原因是本仓库是**公开仓库** ——
  私钥一旦进过 git 历史就再也收不回来，任何人都能为「你的产品」签更新包，
  这是供应链投毒的最短路径。

- **私钥自动从旧路径迁移到新路径** — 它最强的理由是**用户体验最好**：
  用户升级后不必知道密钥在哪，脚本自己找过去搬好，两代目录的过渡完全透明。
  否掉的原因是上面那三条**不可恢复**的失败路径 ——
  私钥丢失等于永久失去为已发布客户端签名的能力，而自动搬运把它变成一次
  断电就能触发的事故。透明性不值得用不可逆性去换。

- **把口令写进脚本注释或示例** — 它最强的理由是**便于复现构建**：注释里写清楚
  口令长什么样、放哪，新人照着就能跑。否掉的原因同上：任何被 git 跟踪的文件
  都是公开的，口令写进注释等于公开。

## Consequences

- **收益**：私钥不可能因一次误操作而丢失或被覆盖；泄露面为零。
- **收益**：密钥与仓库解耦，换机器 / 换目录都不影响签名能力。
- **代价与已知上限**：默认探测路径在本机不成立，每次构建都要显式传参 ——
  这是刻意保留的摩擦，让人**知道自己在用哪把密钥**。
  **信号**：若将来改用硬件 / 系统级密钥库（OS 凭据管理器、硬件令牌），
  「路径解析 + 回退」这套可以整体退役 —— 但那时仍要保留
  「**不自动搬运**」这条原则（换成「不自动导出」）。
- **代价**：`release.yml` 头部注释与实际口径已分叉过一次，属于「文档与代码分叉」
  清单里的已知项，靠注释指向 `Resolve-KeyPath` 维持。

## Verification

- 脚本四步（`scripts/build-signed.ps1`）：`[1/4]` 检查私钥存在非空且首行是 minisign
  私钥 → `[2/4]` **实际签一次**校验口令与密钥配对 → `[3/4]` 强制重建内嵌网关并做
  双端 SHA256 指纹比对 → `[4/4]` `tauri build`。
- 仅校验不构建：`-CheckOnly`（非交互场景**必须先跑它**，见上面缺口令阻塞的坑）。
- 公开仓库纪律：`.gitignore` 排除 `*.key` / `*.key.pub`；
  **具体本机绝对路径不进仓库文档**（判据是「别人 clone 到就成立」）。
