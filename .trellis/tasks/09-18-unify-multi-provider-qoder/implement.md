### 步骤
1. 账号加载层：识别两个产品前缀，归入同一候选池
2. 成本维度：作为 `tierWeightOf` 的**新增小乘子**（不是塞回 credits）
   - 倍率三态：未声明 → 中性 1
   - 校准值做成**可注入参数**，便于单测
3. 到期维度：Qoder 的 `rewardExpiresAt` 接进到期分层
   - 拿不到时按既有"到期未知排最后"处理
4. 界面/日志：显示本次实际命中的产品（避免用户不知道烧了哪份额度）

### 验证
- [ ] **分布测试**（可注入随机源，跑 N 次）：
  - [ ] 两产品都被选中（不是饿死一方）
  - [ ] 更便宜的一方份额更高
  - [ ] 快到期的一方优先
  - [ ] 成本未声明时退化为中性（份额不塌成 0）
- [ ] 现有 WorkBuddy 路由测试全绿（**不得改动其期望值**）
- [ ] 真实调用：两产品的同名模型都能调通

### 风险与回滚点
跨产品权重是最容易"悄悄改变现有行为"的地方。
**回滚策略**：产品维度做成开关，关闭即回到单产品候选池。
